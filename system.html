1. Project Overview & Confirmed Decisions

The HKB Attendance Management System is a centralized, web-based platform tailored specifically to security operations. The system manages staff registration, shift-based attendance recording, document-backed leave processing, transfer workflows, and payroll-aligned reporting.

Confirmed Business Parameters

  • • Registration Data: Name, Age, Phone, Employee ID, Reg Date, Kin Name, Kin Relation, Kin Phone, Home Location, Work Location.
  • • Authentication: Google OAuth 2.0 mandatory for 100% of accounts.
  • • Shift Cadence: Attendance taken on a per-shift basis (Day/Night shifts).
  • • Absence Processing: Absences classified as Sick, Permitted Reason (with allowed days), or Not Permitted.
  • • Sick Leave Validation: Requires medical document upload stored via Firebase.
  • • Guard Role Access: View-only permissions for guards/Askari.
  • • Transfer Authorization: Restricted strictly to Super Admin and HR roles.
  • • Reporting Constraints: Reports generated exclusively in PDF format.

3. Architecture & Technology Stack

Core Framework & Deployment

Next.js 14+ (App Router): React Server Components for performance, Server Actions for mutations, dynamic rendering.

Tailwind CSS & TSX: Strict type safety and responsive UI components for desktop and mobile devices.

Vercel Edge Network: Host infrastructure for global edge caching and fast serverless execution.

Database, Caching & Files

Neon Serverless Postgres: Branchable PostgreSQL database providing serverless auto-scaling.

Drizzle ORM: Type-safe SQL builder with efficient migration tooling and minimal query overhead.

Upstash Redis: Rate limiting, distributed session locking, and instant caching of active shift sessions.

Firebase Storage: Secure cloud storage bucket for medical certificates and sick leave PDFs.

4. Shift & Absence Workflow Business Logic

Absence Classification Rules

SICK Mandatory fields: Start Date, Expected Return, Doctor's Note Upload (Firebase URL). Requires HR review status.
PERMITTED REASON e.g., Funeral/Family Emergency. System validates input against maximum approved days threshold (`allowed_days`).
NOT PERMITTED Absence without prior authorization. Flags account for payroll deduction via Bursar reports.

6. Database Schema (Drizzle ORM for Neon Postgres) 

import { pgTable, uuid, varchar, integer, timestamp, date, text, pgEnum } from 'drizzle-orm/pg-core';

export const roleEnum = pgEnum('user_role', [
  'SUPER_ADMIN', 'SENIOR_SUPERVISOR', 'SUPERVISOR', 'HR', 'BURSAR', 'GUARD'
]);

export const shiftTypeEnum = pgEnum('shift_type', ['DAY', 'NIGHT']);
export const attendanceStatusEnum = pgEnum('attendance_status', ['PRESENT', 'ABSENT']);
export const absenceCategoryEnum = pgEnum('absence_category', ['SICK', 'PERMITTED_REASON', 'NOT_PERMITTED']);
export const transferStatusEnum = pgEnum('transfer_status', ['PENDING', 'APPROVED', 'REJECTED']);

// Core Users Table
export const users = pgTable('users', {
  id: uuid('id').defaultRandom().primaryKey(),
  googleId: varchar('google_id', { length: 255 }).notNull().unique(),
  email: varchar('email', { length: 255 }).notNull().unique(),
  fullName: varchar('full_name', { length: 255 }).notNull(),
  role: roleEnum('role').notNull().default('GUARD'),
  createdAt: timestamp('created_at').defaultNow().notNull(),
});

// Guard Profiles (Extends User Data)
export const guardProfiles = pgTable('guard_profiles', {
  id: uuid('id').defaultRandom().primaryKey(),
  userId: uuid('user_id').references(() => users.id).notNull(),
  employeeId: varchar('employee_id', { length: 50 }).notNull().unique(),
  age: integer('age').notNull(),
  phone: varchar('phone', { length: 20 }).notNull(),
  homeLocation: varchar('home_location', { length: 255 }).notNull(),
  workLocation: varchar('work_location', { length: 255 }).notNull(),
  kinName: varchar('kin_name', { length: 255 }).notNull(),
  kinRelation: varchar('kin_relation', { length: 100 }).notNull(),
  kinPhone: varchar('kin_phone', { length: 20 }).notNull(),
  registrationDate: date('registration_date').notNull(),
  assignedSupervisorId: uuid('assigned_supervisor_id').references(() => users.id),
});

// Per-Shift Attendance Logs
export const attendanceLogs = pgTable('attendance_logs', {
  id: uuid('id').defaultRandom().primaryKey(),
  guardId: uuid('guard_id').references(() => guardProfiles.id).notNull(),
  supervisorId: uuid('supervisor_id').references(() => users.id).notNull(),
  date: date('date').notNull(),
  shift: shiftTypeEnum('shift').notNull(),
  status: attendanceStatusEnum('status').notNull(),
  absenceCategory: absenceCategoryEnum('absence_category'),
  allowedDays: integer('allowed_days'),
  reason: text('reason'),
  documentUrl: text('document_url'), // Firebase File URL for Sick Notes
  createdAt: timestamp('created_at').defaultNow().notNull(),
  updatedAt: timestamp('updated_at').defaultNow().notNull(),
});

// Guard Transfers Table
export const transferRequests = pgTable('transfer_requests', {
  id: uuid('id').defaultRandom().primaryKey(),
  guardId: uuid('guard_id').references(() => guardProfiles.id).notNull(),
  fromSupervisorId: uuid('from_supervisor_id').references(() => users.id).notNull(),
  toSupervisorId: uuid('to_supervisor_id').references(() => users.id).notNull(),
  requestedBy: uuid('requested_by').references(() => users.id).notNull(),
  approvedBy: uuid('approved_by').references(() => users.id),
  status: transferStatusEnum('status').default('PENDING').notNull(),
  reason: text('reason').notNull(),
  createdAt: timestamp('created_at').defaultNow().notNull(),
});

7. Backend REST API Specifications

GET /api/v1/attendance/shift-sheet

Query Params: supervisorId, date, shift (DAY|NIGHT)

Auth: Supervisor, Senior Supervisor, Admin

POST /api/v1/attendance/log

Payload: { guardId, shift, status, absenceCategory?, allowedDays?, reason?, documentUrl? }

Auth: Supervisor, Senior Supervisor

PUT /api/v1/transfers/:id/action

Payload: { action: "APPROVE" | "REJECT", reviewerNotes?: string }

Auth: Super Admin, HR Personnel Only

GET /api/v1/reports/pdf

Query Params: startDate, endDate, supervisorId?, format=pdf

Auth: Bursar, HR, Super Admin
